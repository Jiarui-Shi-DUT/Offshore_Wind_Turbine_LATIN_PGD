# FOM-OPT5-PILOT：截面内 16 纤维材料点批量化试验

## 1. 阶段定位

本阶段不是生产优化，而是一个公平性诊断试验。

提出该试验的原因是：LATIN-PGD 在局部阶段已经采用材料点方向的 NumPy 批量化，因此需要检查全阶模型 FOM 是否也能从同类实现优化中受益。

本阶段只测试：

> 将每个纤维截面内原本逐根执行的 16 个纤维材料点 RK4 本构积分，改为一次 NumPy 批量推进。

不改变：

- 一维黏塑性损伤本构；
- RK4 时间积分格式；
- 纤维截面离散；
- 中心差分数值切线；
- Newton 迭代；
- 时间步长；
- 网格与加载；
- 收敛容限。

本阶段仅为 monkey patch 单周期 A/B pilot，不修改生产源码。

---

## 2. 为什么需要测试

LATIN-PGD OPT-4 已经证明：

- 时间方向必须顺序推进；
- 不同材料点在同一时间位置上彼此独立；
- 对当前同质材料塔筒，可以沿材料点方向进行批量计算。

LATIN-PGD 的正式塔筒算例一次批量处理约 320 个材料点。

当前 FOM 的自然局部计算粒度不同：

- 每个纤维截面有 16 根纤维；
- 每次截面材料积分原本逐纤维执行 16 次标量 RK4；
- 截面中心差分切线会重复调用多次纤维积分。

因此需要实际测试：

> 对 FOM 来说，16 个纤维材料点的批量化究竟能否获得实际性能收益。

---

## 5. 为什么 LATIN-PGD 批量化有效，而 FOM 当前 16 纤维批量化反而更慢

关键区别不是数学模型，而是一次批处理的规模。

LATIN-PGD：

```text
一次约处理 320 个材料点
```

FOM 当前试验：

```text
一次只处理 16 个纤维材料点
```

NumPy 批量运算自身存在一定固定开销，例如：

- 创建和组织数组；
- `np.where`；
- `np.maximum`；
- `np.clip`；
- 临时数组构造。

当一次处理 320 个材料点时，这些开销可以被大量材料点摊薄。

当一次只有 16 个材料点时，批量运算的固定开销反而可能超过省掉的 Python 循环成本。

因此：

> 批量化是否有效不能只根据算法形式判断，必须以实际计算粒度和实测结果为准。

---

## 6. 公平性结论

本试验说明：

> FOM 并不是没有考虑材料点批量化，而是已经对与 LATIN-PGD 同类的材料点批量化思路进行了实际 A/B 测试。

结果为：

- LATIN-PGD：320 材料点方向批量化有效，因此保留；
- FOM：16 纤维截面内批量化性能下降，因此不采用。

公平比较并不要求两种方法使用完全相同的代码形式，而应要求：

> 在不改变各自数学方法的前提下，对适用的实现级优化进行评估，并采用各自实测更高效的实现。

因此，保留 LATIN-PGD 的材料点批量化，同时保留 FOM-OPT4 的逐纤维标量路径，是当前更合理的公平实现选择。
