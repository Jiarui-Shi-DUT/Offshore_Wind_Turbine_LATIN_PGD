## 1. 本阶段目标

本阶段的核心目标不是继续追求某一侧的局部代码加速，而是回答一个更重要的问题：

> 在 FOM 与 LATIN-PGD 都经过充分实现级优化之后，两种方法在相同海上风机塔筒循环损伤问题上的实际计算效率如何。

此前的原始效率比较存在一个明显问题：

> 原始 FOM 中包含大量可以消除的实现开销，因此直接用旧 FOM 与优化后的 LATIN-PGD 比较，不能代表方法层面的公平效率差异。

因此，本阶段先后完成：

1. LATIN-PGD 实现级优化；
2. FOM 实现级优化；
3. FOM 材料点批量化可行性试验；
4. 两种优化后实现的统一正式 benchmark；
5. 1、2、5、10 周期三次独立重复试验；
6. 精度与效率同步校核。

最终正式比较对象定义为：

```text
FOM,opt      = 当前 FOM-OPT4 稳定实现
LATIN,opt    = 当前 LATIN-PGD OPT6 稳定实现
```

## 2. 为什么当前比较比旧比较更公平

### 2.1 FOM 已经完成实现级优化

当前 FOM 已先后完成：

- FOM-OPT1：标量损伤截断；
- FOM-OPT2：RK4 与材料速率标量化；
- FOM-OPT3：RK4 状态有限性检查标量化；
- FOM-OPT4：纤维截面应力专用求值；
- FOM-OPT5-PILOT：16 纤维材料点批量化试验。

其中 FOM-OPT5-PILOT 得到：

```text
数值等价性：PASS
性能收益：FAIL
生产落地：NO
```

16 纤维批量化从：

```text
2.756740 s
```

变为：

```text
3.053992 s
```

性能下降约：

```text
10.783%
```

因此当前 FOM 保留更快的逐纤维标量路径。

### 2.2 LATIN-PGD 已经完成实现级优化

LATIN-PGD 已完成的主要优化包括：

- 标量损伤截断；
- 常量缓存；
- RK4 结构扁平化；
- 同质材料点方向 NumPy 批量化；
- 固定点收敛容限标定；
- 受保护的 Aitken 加速。

其中材料点批量化采用：

```text
时间方向顺序推进
+
材料点 q 方向批量计算
```

当前标准塔筒共有：

```text
Nq = 320
```

个材料点。

### 2.3 公平性的核心原则

本阶段采用的原则不是：

> 两种方法必须使用完全相同的代码写法。

而是：

> 在不改变各自数学方法的前提下，对适用的实现级优化进行评估，并分别采用实测更高效的稳定实现。

因此：

- LATIN-PGD 保留 320 材料点批量化；
- FOM 保留 16 纤维逐点标量积分；

仍然属于公平比较。

- 最大荷载：`+1.0 MN`

$$N_t=40n+1.$$

- 总材料点数：320；
- 相同塔筒几何；

## 4. 正式计时口径

### 4.1 FOM

FOM 计时包围：

```text
run_nonlinear_asymmetric_analysis(...)
```

包含：

- 网格与系统构建；
- 预加载；
- 全部周期非线性求解；
- Newton 迭代；
- 完整位移、应变、应力、内部变量历史保存；
- 最终响应组装。

### 4.2 LATIN-PGD

LATIN-PGD 分为：

```text
LATIN setup
+
LATIN solver
=
LATIN total
```

其中 setup 包含：

- 几何与网格；
- 塔筒系统；
- 平衡算子；
- 荷载向量；
- 弹性全历史初始化。

solver 包围：

```text
solve_tower_latin_pgd(...)
```

正式公平效率指标定义为：

$$S_{\mathrm{fair}}=\frac{\operatorname{median}(t_{\mathrm{FOM,opt}})}{\operatorname{median}(t_{\mathrm{LATIN,opt,total}})}.$$

解释为：

- `S_fair` 大于 1：LATIN-PGD 更快；
- `S_fair` 等于 1：两者接近；
- `S_fair` 小于 1：FOM 更快。

## 16. 实现优化收益与方法效率必须分开

后续论文或汇报中建议严格区分三类指标。

### 16.1 FOM 实现优化收益

定义：

$$S_{\mathrm{FOM,impl}}=\frac{t_{\mathrm{FOM,old}}}{t_{\mathrm{FOM,opt}}}.$$

10 周期粗略对应：

$$S_{\mathrm{FOM,impl}}\approx\frac{307.891}{22.851}=13.47.$$

### 16.2 LATIN-PGD 实现优化收益

定义：

$$S_{\mathrm{LATIN,impl}}=\frac{t_{\mathrm{LATIN,old}}}{t_{\mathrm{LATIN,opt}}}.$$

10 周期粗略对应：

$$S_{\mathrm{LATIN,impl}}\approx\frac{467.362}{24.985}=18.71.$$

### 16.3 方法层面的公平效率

最终应该报告：

$$S_{\mathrm{fair}}=\frac{t_{\mathrm{FOM,opt}}}{t_{\mathrm{LATIN,opt}}}.$$

10 周期：

$$S_{\mathrm{fair}}=0.914599.$$

因此：

> 实现优化可以非常显著，但实现优化收益不能直接等价为 LATIN-PGD 相对 FOM 的模型降阶收益。

这是后续学术表述中必须严格区分的地方。

## 17. 当前最重要的科研认识

### 17.1 低秩表示能力已经得到支持

时间点：

```text
41 -> 401
```

PGD rank：

```text
11 -> 21
```

因此当前循环响应确实表现出明显的低秩结构。

### 17.2 低秩不自动等于计算加速

尽管 rank 增长缓慢，LATIN-PGD wall-time 仍然比 FOM 增长更快。

因此真正需要研究的是：

> LATIN-PGD 中哪些全时间域操作、固定点迭代、Trial A/B、时间函数更新或其他步骤，使实际成本没有随低 rank 同比例降低。

### 17.3 优化后的 LATIN-PGD 并不是简单地“比 FOM 慢”

当前实际关系是：

```text
1 cycle   LATIN-PGD 明显更快
2 cycles  LATIN-PGD 明显更快
5 cycles  LATIN-PGD 仍然更快
10 cycles FOM 略快
```

因此更准确的表述应该是：

> 当前实现存在一个随时间域扩大而出现的效率 crossover，而不是 LATIN-PGD 在所有规模下都快或都慢。

### 17.4 当前精度不是主要矛盾

10 周期时：

```text
应力全历史误差      ≈ 0.138%
塑性应变全历史误差  ≈ 0.999%
损伤全历史误差      ≈ 0.945%
```

因此当前进一步研究的优先级应从：

```text
继续盲目收紧 LATIN 收敛容限
```

转向：

```text
解释和改善长时间域计算成本增长
```

## 18. 当前阶段结论

本阶段可以正式记录：

> **FOM,opt 与 LATIN-PGD,opt 的 1、2、5、10 周期公平效率 benchmark 已完成。**

当前结论为：

1. 两种实现均已经完成主要实现级性能优化；
2. 1–10 周期精度稳定，没有出现误差累积失控；
3. LATIN-PGD 在 1、2、5 周期仍具有 wall-time 优势；
4. 10 周期时 FOM 略快，差距约 9%；
5. 效率 crossover 被当前测试点夹在 5–10 周期之间；
6. PGD rank 增长缓慢，但 LATIN-PGD wall-time 增长仍偏快；
7. 当前后续研究重点应转向 LATIN-PGD 长时间域成本来源，而不是继续优化 FOM。

## 19. 下一步建议

下一阶段暂时不建议直接进入 100 周期正式计算。

更合理的顺序是：

1. 固化本次公平 benchmark；
2. 将 `FOM,opt = FOM-OPT4` 作为当前公平参考基线；
3. 重新分析 LATIN-PGD 1、2、5、10 周期的各模块耗时随 `Nt` 的增长；
4. 重点识别导致 LATIN-PGD 超线性增长的模块；
5. 判断这些成本属于算法本身还是仍可消除的实现开销；
6. 只有在这一问题解释清楚后，再决定是否进入 20、50、100 周期规模扩展。

当前最关键的问题已经从：

> LATIN-PGD 到底能不能计算塔筒循环损伤？

转变为：

> 在已经证明精度和低秩结构之后，如何让这种低秩结构真正转化为长时间域计算效率优势？
