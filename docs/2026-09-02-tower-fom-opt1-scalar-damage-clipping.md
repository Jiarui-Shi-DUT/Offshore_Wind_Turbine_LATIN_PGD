# FOM-OPT1：塔筒全阶模型标量损伤截断优化与公平效率基线重建

**日期：** 2026-09-02
**分支：** `perf/tower-fom-optimization`
**生产代码提交：** `d7cf9c6` — `perf: optimize scalar damage clipping for tower FOM`

---

## 1. 阶段背景

在此前的塔筒 LATIN-PGD 效率优化中，10 周期非对称循环算例的 LATIN-PGD 求解时间已经由早期约 `467 s` 降低到 OPT-6 阶段约 `24 s`。但此前用于比较的 FOM 仍是早期实现版本，其 10 周期耗时约为 `300 s`。

这意味着，如果直接采用

$$
S = \frac{t_{\mathrm{FOM,old}}}{t_{\mathrm{LATIN,opt}}}
$$

作为算法加速比，会混合两类因素：

1. FOM 本身的实现层额外开销；
2. LATIN-PGD 的模型降阶与算法优化收益。

因此，本阶段不继续推进 LATIN-PGD 的下一轮优化，而是建立独立分支

`perf/tower-fom-optimization`

对 FOM 进行同等标准的实现层性能审查和优化，目标是重新建立可用于严肃 FOM–LATIN-PGD 比较的公平效率基线。

最终应采用

$$
S_{\mathrm{fair}}
=
\frac{t_{\mathrm{FOM,opt}}}
     {t_{\mathrm{LATIN,opt}}}
$$

而不是使用未经优化的旧 FOM 作为分母比较对象。

## 4. 主要性能热点

函数级 profiling 表明，当前 FOM 的主要成本集中在材料积分和截面数值切线链路。

关键累计调用统计为：

| 函数/过程 | 调用次数 | 累计时间 |
|---|---:|---:|
| `solve_nonlinear_tower_load_step` | 410 | `456.508 s` |
| `set_trial_displacements`（塔筒） | 1042 | `450.824 s` |
| `set_trial_deformation`（截面） | 20840 | `449.161 s` |
| `_integrate_fibers` | 104200 | `446.533 s` |
| `rk4_step` | 1667200 | `380.290 s` |
| `_numerical_tangent` | 20840 | `358.315 s` |
| `safe_damage` | 33738560 | `353.060 s` |
| `state_rate` | 6668800 | `336.569 s` |
| `np.clip` | 33738600 | `340.215 s` |

### 4.1 Newton 并不是当前首要问题

10 周期共有 410 个非线性荷载步，对应 1042 次塔筒 trial evaluation，因此平均每个荷载步约为

$$
\frac{1042}{410}
\approx 2.54
$$

次 trial evaluation。

最大 Newton 迭代数仅为 4。

因此，当前 FOM 的高耗时并不是由 Newton 严重不收敛或迭代次数异常偏大导致的。

### 4.2 数值切线导致大量重复材料积分

当前截面 trial 计算中：

1. 首先对真实 trial deformation 进行一次完整纤维积分；
2. 若需要切线，则中心差分分别计算：
   - 轴向应变正扰动；
   - 轴向应变负扰动；
   - 曲率正扰动；
   - 曲率负扰动。

因此一次带切线的截面 trial 实际包含：

$$
1 + 4 = 5
$$

次完整纤维材料积分。

profiling 中也满足：

$$
104200 = 20840 \times 5
$$

说明当前 80% 的 `_integrate_fibers` 调用与数值切线扰动有关。

这一部分是后续 FOM 优化的重要候选，但由于它涉及 Newton 切线构造方式，必须单独进行严格数值等价验证，不能在 FOM-OPT1 中直接修改。

## 5. FOM-OPT1 的问题定位

当前材料模型中的 `safe_damage()` 原实现为：

```python
return float(
    np.clip(
        damage,
        0.0,
        material.damage_upper_bound,
    )
)
```

这里的 `damage` 是标量，但每次调用都进入 NumPy 的通用数组函数调度链。

10 周期 profiling 中：

- `safe_damage` 调用约 `3.3739 × 10^7` 次；
- `np.clip` 调用约 `3.3739 × 10^7` 次；
- 大量自身耗时集中在：
  - `_clip_dep_is_scalar_nan`；
  - `_clip`；
  - `ndim`；
  - `_wrapit`；
  - `implement_array_function`。

这些操作并不改变材料模型的物理或数学定义，而是标量通过 NumPy 通用数组接口时产生的实现层调度开销。

## 6. FOM-OPT1 修改

生产代码仅修改：

`material/viscoplastic_damage_1d.py`

中的 `safe_damage()`。

修改后：

```python
value = float(damage)
upper_bound = float(material.damage_upper_bound)
if value < 0.0:
    return 0.0
if value > upper_bound:
    return upper_bound
return value
```

该修改保持与原有

$$
D_{\mathrm{safe}}
=
\min\left[
\max(D,0),
D_{\max}
\right]
$$

完全相同的标量截断定义。

本阶段没有修改：

- 材料本构方程；
- RK4 积分格式；
- 时间步长；
- Newton 方法；
- Newton 收敛容限；
- 截面数值切线；
- 塔筒有限元离散；
- 荷载历史；
- 输出历史定义。

因此 FOM-OPT1 属于纯实现层优化。

## 10. 本阶段最重要的科研认识

### 10.1 旧 FOM 不能继续作为最终效率比较基线

此前约 `300 s` 的 10 周期 FOM wall-time 中包含显著实现层开销。

仅消除标量 `np.clip` 调度，就可以把一次 10 周期运行从：

`292.869827 s`

降低到：

`58.863949 s`

且完整场和 Newton 路径完全不变。

因此，以前使用未经同等优化的 FOM 与已经经过多轮优化的 LATIN-PGD 直接计算加速比，会显著高估 LATIN-PGD 相对于高质量 FOM 实现的算法效率优势。

### 10.2 需要区分三类“加速”

后续正式结果应分别报告：

FOM 实现优化收益：

$$
S_{\mathrm{FOM,impl}}
=
\frac{t_{\mathrm{FOM,old}}}
     {t_{\mathrm{FOM,opt}}}
$$

LATIN-PGD 实现优化收益：

$$
S_{\mathrm{LATIN,impl}}
=
\frac{t_{\mathrm{LATIN,old}}}
     {t_{\mathrm{LATIN,opt}}}
$$

以及真正用于方法比较的：

$$
S_{\mathrm{method}}
=
\frac{t_{\mathrm{FOM,opt}}}
     {t_{\mathrm{LATIN,opt}}}
$$

只有第三个指标才适合作为最终“优化 FOM 与优化 LATIN-PGD”的公平效率比较。

### 10.3 当前 58.86 s 仍不是最终 FOM 正式基准

`58.863949 s` 来自一次 10 周期 A/B 验证中的候选运行。

它足以证明 FOM-OPT1 的优化收益和数值等价性，但还不能直接作为最终论文或汇报中的正式 `t_FOM,opt`。

正式 wall-time 仍应在 FOM 优化阶段稳定后采用统一计时协议：

- 同一机器；
- 同一 Python 环境；
- 明确 warm-up 策略；
- 至少 3 次重复；
- 报告中位数及离散程度；
- 对 1、2、5、10 周期统一测试；
- FOM 与 LATIN-PGD 采用一致的计时边界定义。

## 11. 下一步

FOM-OPT1 之后，下一步不应立即修改 Newton 收敛容限。

当前 profiling 已经显示：

- Newton 最大迭代数仅为 4；
- 平均 trial evaluation 数约 2.54/荷载步；
- 截面中心差分数值切线触发了大量重复材料积分。

因此下一阶段应首先重新 profiling 已经落地 FOM-OPT1 的生产代码，得到新的热点排序。

只有在确认 FOM-OPT1 后的主导瓶颈后，再决定是否进入：

**FOM-OPT2：截面数值切线重复材料积分优化**

该优化必须独立验证：

- Newton 收敛路径；
- 平衡残差；
- 完整节点位移历史；
- 完整纤维应变、应力和内部变量；
- 多周期损伤累积；
- wall-time 收益。

在没有完成这些验证之前，不应将切线算法修改作为正式 FOM 基线的一部分。
